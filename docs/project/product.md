# Продукт и предметная область

## Цель
«Иви» — семейная система для учета событий по одному питомцу, собаке по имени Иви.

Первый этап дал локальный Android MVP: историю событий, веса и напоминаний без лишней сложности. Следующая цель — связка Android-клиента и отдельного backend-приложения с синхронизацией между устройствами для двух пользователей.

## Обязательные договоренности
- Приложение называется «Иви» и делается для личного семейного использования.
- В MVP один питомец, локальный учет событий, история веса и локальные напоминания.
- Локальный Android MVP остается рабочей базой; ломать его ради архитектурной красоты нельзя.
- Backend нужен для общего доступа двух пользователей и синхронизации.
- NAS Synology рассматривается только как будущий слой резервного копирования, не primary storage.

## Язык и тексты
- Общение с пользователем только на русском языке.
- Проектную документацию вести на русском языке.
- Все пользовательские тексты в приложении должны быть на русском языке.
- Пользователь не должен видеть технические имена вроде `eventType`, `eventDate`, `notificationEnabled`.

## Границы MVP
Входит:
- карточка одного питомца;
- история веса;
- справочник типов событий;
- список, создание и редактирование событий;
- статусы событий;
- локальные напоминания с глобальными настройками;
- современный UI на Compose;
- архитектурная база под синхронизацию.

Не входит:
- web-версия;
- несколько питомцев;
- сложная ролевая модель;
- вложения и документы;
- история изменений пользователей;
- серверные push-уведомления;
- хранение основной базы на NAS.

## Предметная модель

### Питомец
Поля:
- `id`
- `name`
- `birthDate`
- `photoUri`
- `createdAt`
- `updatedAt`

Правило: приложение пока для одного питомца, но имя и данные не должны быть захардкожены.

### Запись веса
Поля:
- `id`
- `petId`
- `date`
- `weightGrams`
- `comment`
- `createdAt`

Правило: текущий вес определяется по последней актуальной записи, а не хранится отдельным обязательным полем.

### Тип события
Поля:
- `id`
- `name`
- `category`
- `defaultDurationDays`
- `isActive`
- `colorArgb`
- `iconKey`
- `createdAt`
- `updatedAt`

Примеры: Бравекто 3, Симпарика, Прививка, Глистогонное, Осмотр.

Категории фиксированы на первом этапе: От клещей, От глистов, Прививка, Осмотр, Другое.

### Событие питомца
Поля:
- `id`
- `petId`
- `eventTypeId`
- `eventDate`
- `dueDate`
- `comment`
- `notificationsEnabled`
- `status`
- `createdAt`
- `updatedAt`

Статусы:
- `ACTIVE`
- `COMPLETED`
- `ARCHIVED`

Правила:
- время не используется, только дата;
- дата события обязательна;
- `dueDate` может быть рассчитана от `eventDate + defaultDurationDays`, но пользователь может изменить ее вручную;
- новые события создаются как `ACTIVE`;
- события сортируются по убыванию `eventDate`;
- напоминания планируются только для `ACTIVE` с заполненной `dueDate` и включенными уведомлениями;
- `COMPLETED` и `ARCHIVED` не планируют новые напоминания.

### Глобальные настройки напоминаний
Поля:
- `id`
- `firstReminderEnabled`
- `firstReminderDaysBefore`
- `secondReminderEnabled`
- `secondReminderDaysBefore`
- `createdAt`
- `updatedAt`

Правила:
- настройки едины для приложения;
- напоминания локальные;
- фактические даты рассчитываются от `dueDate`.

## Бизнес-правила
- В приложении один питомец в рамках MVP.
- Имя питомца и фото редактируемые.
- Типы событий нельзя физически удалять, если по ним уже есть события; их нужно деактивировать.
- Из UI для редактирования типа события доступна кнопка удаления: без связанных событий тип удаляется физически, при наличии связанных событий деактивируется.
- Событие всегда привязано к типу события.
- Все пользовательские формулировки должны быть короткими, понятными и неканцелярскими.

## Визуальное направление
Образ приложения:
- мягкий;
- домашний;
- дружелюбный;
- аккуратный;
- не корпоративный;
- не старый CRUD.

UI-принципы:
- светлый теплый фон;
- палитра в духе окраса кавалер кинг чарльз спаниеля;
- мягкие бело-рыжие оттенки;
- теплые кремовые и карамельные акценты;
- темный читаемый текст;
- карточки, секции, чипы и хорошие отступы.

## Экраны
- Главный экран Иви.
- Экран событий.
- Экран добавления и редактирования события.
- Экран типов событий.
- Экран веса.
- Экран настроек напоминаний.
- Экран редактирования питомца.

## UI-подход
Главный экран — обзор текущего состояния, а не просто список: карточка питомца, фото, возраст, текущий вес, ближайший важный блок, актуальные события и быстрые действия.

Форма события должна быть короткой и сгруппированной по смыслу: основные данные, статус, уведомления.

Экран веса показывает текущий вес крупно и историю записей. График не обязателен для MVP.

Экран настроек объясняет правила напоминаний простым языком.
